# PRD — 손으로 넘기는 웹툰 (Hand-Turned Toon)

> 작성일: 2026-11-19 · 상태: 초안 v0.1
> 관계 문서: `docs/PLAN.md`(기획·일정), `CLAUDE.md`(코딩 규칙), `webtoon.md`(스토리·컷 콘티)
> 이 문서는 **무엇을, 어떤 기준으로 완성이라 부를지**를 정한다. 일정과 작업 순서는 PLAN.md를 따른다.

## 1. 문제와 목표

**문제.** 웹툰은 스크롤만 하는 수동적 콘텐츠다. 클릭형 인터랙션은 "누르는 이유"가 약해 몰입을 만들지 못한다.

**해결 가설.** 손동작을 장면 속 사건(문을 친다, 컷을 밀어낸다)과 1:1로 묶으면, 입력 자체가 이야기의 일부가 되어 몰입감이 커진다.

**제품 목표**

| # | 목표 | 측정 기준 |
| --- | --- | --- |
| G1 | 카메라 모드로 에피소드를 끊김 없이 완주 | 테스트 참가자 5명 중 4명 이상이 도움 없이 완주 |
| G2 | 카메라 없이도 동일한 이야기 완주 | 키보드·클릭만으로 전 장면 통과 (자동 테스트) |
| G3 | 제스처 판정이 "답답하지 않을" 정도로 정확 | 4.3절 정확도 기준 충족 |
| G4 | 포트폴리오에서 설계를 설명 가능 | README + 아키텍처 그림 + 오인식 개선 기록 + 30초 데모 영상 |

**비목표 (이번 범위에서 하지 않음)**

- 여러 에피소드, 회원·저장 기능, 서버·DB
- 두 손 동시 인식(판정은 첫 번째 손만. 손이 2개 보이면 "한 손만 보여주세요" 안내), 커스텀 제스처 모델 학습(Model Maker)
- 모바일 카메라 모드의 완성도 보장 (모바일은 키보드·터치 모드 완주만 보장, 카메라는 best-effort)
- Three.js 등 3D 연출

## 3. 범위

### 3.1 MVP (M1~M3)

장면: **S0 인트로 → S1 잠긴 문 → S2 복도 → S5 엔딩 → 결과**

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| F-01 | 카메라 연결 | "손으로 읽기" 클릭 시 권한 요청. 허용 시 3초 내 미리보기 표시 |
| F-02 | 대체 모드 자동 전환 | 권한 거부·카메라 없음·사용 중·모델 로딩 10초 초과 시 안내 문구와 함께 키보드·클릭 모드로 전환. 재시도 버튼 제공 |
| F-03 | 손 인식 미리보기 | 우측 하단 소형 영상 + 21개 점. 손 미검출 시 회색 테두리, 검출 시 강조색 |

| F-05 | 키보드·클릭 대응 | H=PALM_SHOW, Space=PUNCH, ←/→=SWIPE, Enter=THUMB_UP. 화면의 안내 아이콘 클릭도 같은 이벤트 발생 |
| F-06 | 장면 상태 머신 | 장면 순서·요구 제스처·필요 횟수·다음 장면을 `scenes/data/episode1.ts`에서 읽음. 요구되지 않은 이벤트는 무시 |
| F-07 | S1 문 파괴 연출 | PUNCH 1·2회차 금 가는 이미지 + 흔들림, 3회차 파편(Canvas) 후 S2 |

| F-09 | 판정 직전 피드백 | 주먹을 쥐면 문이 살짝 흔들림, 손바닥 유지 중엔 진행 링 표시 |
| F-10 | 막힘 구제 | 한 장면 15초 경과 시 "건너뛰기" 버튼 노출 |
| F-11 | 결과 화면 | 소요 시간·사용한 입력 방식·PUNCH 횟수 표시, 다시 보기·처음으로 |
| F-12 | 카메라 정지 | `/story` 이탈·탭 닫기 시 스트림 트랙 전부 `stop()` |

## 4. 제스처 명세

### 4.1 인식 엔진

- `@mediapipe/tasks-vision`의 **GestureRecognizer 하나만** 사용한다. 공식 문서 기준 결과에 `gestures`, `handedness`, `landmarks`, `worldLandmarks`가 함께 나오므로 Hand Landmarker를 따로 둘 필요가 없다. (PLAN.md 12장 확인 항목 1 해결)
- `runningMode: "VIDEO"`, `recognizeForVideo(video, timestampMs)`는 동기 호출. timestamp는 단조 증가해야 하므로 `performance.now()`를 쓴다.
- `numHands: 1`, `delegate: "GPU"` 시도 후 실패 시 CPU로 재생성.
- 기본 분류 이름: `None`, `Closed_Fist`, `Open_Palm`, `Pointing_Up`, `Thumb_Down`, `Thumb_Up`, `Victory`, `ILoveYou`.
- wasm·모델 파일은 `public/mediapipe/`에 버전을 고정해 둔다 (공식 예제의 `@latest` CDN은 버전이 바뀔 수 있음). (확인 항목 4 결정)
- 같은 비디오 프레임을 두 번 인식하지 않도록 `video.currentTime`이 바뀐 프레임만 처리한다.

### 4.2 판정 규칙 (시작값, `lib/gestures/config.ts`)

모든 시간 기준은 **프레임 수가 아니라 타임스탬프(ms)** 로 잰다. 저사양 기기에서 FPS가 15로 떨어져도 같은 기준이 유지된다.

| 이벤트 | 판정 | 오인식 방지 | 비고 |
| --- | --- | --- | --- |
| `PALM_SHOW` | `Open_Palm` 500ms 유지 | 중간에 다른 분류가 150ms 넘게 끼면 리셋 | |
| `PUNCH` | 최근 250ms 내 **최종 모양 `fist`**(기본 분류 또는 좌표 판정)가 과반 + 손 크기 30% 이상 증가 | 쿨다운 600ms | 카메라로 뻗은 주먹은 기본 분류가 None/Thumb_Down이 되므로 `Closed_Fist`에 의존하지 않는다. 손 크기 방식은 ※ |
| `SWIPE_LEFT/RIGHT` | 손목 x가 300ms 내 0.25 이상 이동 | 쿨다운 800ms, 쿨다운 중 반대 방향 무시(되돌리는 손 무시) | 방향은 **사용자 시점(거울 반전 후)** 기준 |
| `THUMB_UP` | `Thumb_Up` 500ms 유지 | — | |
| `PALM_HOLD` (확장) | `Open_Palm` 1000ms 유지, 이후 매 프레임 손 중심 전달 | 손 사라지면 즉시 해제 | |
| `FINGER_COUNT` (확장) | 손가락별 "끝–손목 거리 > 둘째 마디–손목 거리"로 펴짐 판정, 엄지는 handedness 기준 x 비교 | 같은 값 700ms 유지 | 단순 y 비교는 손이 기울면 틀림 |

※ PLAN.md의 "손목~중지 뿌리 거리"는 주먹을 카메라 쪽으로 내지를 때 손목이 주먹 뒤로 가려지며 화면상 거리가 오히려 **줄어들 수 있다**. 카메라를 향하는 손등 폭이 더 안정적일 것으로 보고, M1 테스트 페이지(`/lab/punch`)에서 세 방식(손등 폭 / 손목~중지 / 손 전체 사각형)을 나란히 비교한다. z좌표는 손목 기준 상대 깊이라 카메라와의 거리를 알 수 없어 후보에서 뺐다.

※ 손 모양(주먹·손바닥·엄지)은 `lib/gestures/shape.ts`에서 기본 분류가 알아보면 그 값을, 못 알아보면 3D 좌표(손가락 펴짐 비율)로 판정한다. 기본 분류는 손바닥·앞면을 보여줄 때만 잘 동작하기 때문이다.

※ 빠른 동작 중에는 모션 블러로 분류가 `None`이 되거나 손 검출이 잠깐 끊긴다. 그래서 PUNCH는 "모든 프레임이 주먹"이 아니라 "과반이 주먹"으로 본다.

### 4.3 정확도 기준 (M1 관문)

노트북 내장 웹캠, 실내 일반 조명, 거리 40~70cm, 3명 × 각 20회 시도 기준.

| 제스처 | 인식 성공률 | 오인식 (1분간 자연스럽게 손 움직일 때) |
| --- | --- | --- |
| PUNCH | ≥ 80% | ≤ 1회 |
| SWIPE | ≥ 85% | ≤ 1회 |
| PALM_SHOW / THUMB_UP | ≥ 90% | ≤ 1회 |

PUNCH가 기준 미달이면 **"주먹 쥐고 0.4초 유지 = 1타"** 로 단순화한다 (PLAN.md 관문과 동일). 결과는 PLAN.md "오인식 개선 기록"에 남긴다.

## 5. 시스템 요구사항

### 5.1 구조

CLAUDE.md의 데이터 흐름을 그대로 따른다.

```
카메라 → 인식 → 해석(순수 함수) ┐
              키보드·클릭 입력 ┴→ 이벤트 버스 → 장면 상태 머신(useReducer) → 표현
```

- **이벤트 버스는 React 밖의 모듈**이다. `/story` 페이지가 `useEffect`에서 구독하고 `dispatch`로 넘긴다.
- **판정 함수 시그니처:** `(history: FrameSample[], now: number, state: DetectorState) => { event: GestureEvent | null; state: DetectorState }`. 쿨다운처럼 기억이 필요한 값은 `state`로 주고받아 함수 자체는 순수하게 유지한다.
- `FrameSample`은 `lib/vision`이 MediaPipe 결과를 변환한 앱 자체 타입(분류 이름, 21개 좌표, 타임스탬프)이다. `lib/gestures`도 MediaPipe 타입을 직접 import하지 않으므로, 녹화한 JSON으로 테스트할 수 있다.
- **`next/dynamic`의 `ssr: false`는 서버 컴포넌트에서 쓸 수 없다.** 카메라 컴포넌트를 불러오는 래퍼 자체를 `"use client"`로 둔다.
- `/story` → `/result` 이동 시 reducer 상태가 사라지므로 결과 값은 쿼리스트링으로 넘긴다.

### 5.2 `GestureEvent` 타입

```ts
type GestureEvent =
  | { type: 'PALM_SHOW' | 'PUNCH' | 'SWIPE_LEFT' | 'SWIPE_RIGHT' | 'THUMB_UP'; source: 'camera' | 'keyboard' }
  | { type: 'PALM_HOLD'; x: number; y: number; source: 'camera' | 'keyboard' }   // 0~1, 화면 기준
  | { type: 'FINGER_COUNT'; count: 1 | 2 | 3 | 4 | 5; source: 'camera' | 'keyboard' };
```

`source`는 결과 화면 지표와 디버깅용이며, 장면 로직은 `source`로 분기하지 않는다.

### 5.3 비기능 요구사항

| 항목 | 기준 |
| --- | --- |
| 인식 성능 | 기준 노트북(최근 4년 내 내장 그래픽)에서 인식 ≥ 20 FPS, 연출 60 FPS 유지. 입력 영상 640×480 |
| 응답 지연 | 동작 완료 → 연출 시작 ≤ 200ms |
| 첫 로딩 | 모델·wasm 포함 4G 기준 10초 이내, 로딩 진행 표시 |
| 브라우저 | 데스크톱 Chrome·Edge 최신 (카메라 모드 보장), Safari·Firefox·모바일 (키보드·터치 완주 보장) |
| 개인정보 | 영상·좌표를 네트워크로 보내지 않음. 인트로에 명시. 분석 도구 미탑재 |
| 접근성 | 전 제스처 키보드 대응, 컷 `alt` 텍스트, `prefers-reduced-motion` 시 흔들림·번쩍임 약화, 안내 문구 `aria-live` |

## 7. 콘텐츠와 장면 데이터

### 7.1 컷 이미지 (상세 콘티는 `webtoon.md`)

- 총 15장, MVP에 필요한 것은 01~08, 13~15 (11장).
- 800×1200 px WebP, `public/cuts/{번호}-{이름}.webp`. 02~05, 11~12는 같은 구도.
- 대사·말풍선·메모 문구는 이미지에 넣지 않고 장면 데이터의 텍스트를 HTML로 올린다.

### 7.2 장면 데이터 (`src/scenes/data/episode1.ts`)

상태 머신은 아래 5가지 `kind`의 규칙만 알고, 장면 내용은 데이터에서 읽는다.

| kind | 장면 | 데이터 |
